## Executive Summary

The MapLibre GL JS operational map integration across ResQnet has been elevated from technically rendering layer primitives to functioning as a genuine, real-time, interactive **operational situation map** for disaster response.

All three core platform roles (**Citizen**, **Responder**, and **Coordinator**) were verified in live browser sessions with recorded video evidence and high-resolution screenshots. The map immediately communicates **what is dangerous, what is blocked, where incidents and missions are located, where safe hubs are open, and what evacuation routes are recommended**.

---

## 1. Previous Map Problem

Prior to this workstream, the map visually and functionally behaved like a static geographic picture:
- Only generic OpenStreetMap base tiles and standard controls were visibly prominent.
- ResQnet operational layers (Safety Hubs, road states, hazard zones, incident clusters, active missions, evacuation routes) were either invisible, washed out, or indistinguishable from standard OSM roads and icons.
- Responders saw mission instructions on the left panel ("#95 — Inspect Road Survey Mission"), but the map did not answer "Where is this mission?" because missions referencing roads/clusters without explicit point coordinates had their geometry silently dropped.
- MapLibre instance was vulnerable to lifecycle churn, canvas clipping, and lack of resize observer listeners during tab switches or window adjustments.
- Real-time road status changes submitted by field responders and propagated by coordinators were not polled on the responder console without a full page reload.

---

## 2. Root Causes Already Fixed in Earlier Pipeline Repairs

1. **MapLibre Lifecycle Hardening:** Moved `mapRef.current` assignment immediately following MapLibre instance construction rather than inside `map.on('load')`, preventing race conditions during React re-renders.
2. **Style Readiness Synchronization:** Replaced React state `mapLoaded` with ref-based `styleReadyRef.current` to guarantee GeoJSON `setData()` calls never encounter unready style states or stale closures.
3. **OSM Basemap Opacity:** Restored raster tile opacity to `1.0` so geographic context is vivid while operational overlays stand out through high-contrast casings.
4. **Coordinate Filtering for Virtual City:** Added spatial filtering (`isInVirtualCityArea`) to guard the map against disparate test suite coordinates (e.g., Delhi/Chennai) polluting the virtual city viewport `[85.8, 20.5]`.
5. **DOM Marker Cleanup:** Implemented strict marker cleanup routines in `clearMarkers()` to prevent marker stacking across polling intervals.

---

## 3. Additional Improvements Made in This Finalization Phase

1. **Spatial Resolution for Missions Without Explicit Coordinates (Phase 6):**
   - When an operational mission references a road (such as Mission `#95` targeting `road_id: 2`), the map resolves the midpoint coordinate between the road's intersections:
     $$\text{lat} = \frac{\text{from.lat} + \text{to.lat}}{2}, \quad \text{lng} = \frac{\text{from.lng} + \text{to.lng}}{2}$$
   - When a mission references an incident cluster, it resolves the cluster centroid.
   - When a mission references a Safety Hub, it resolves the hub location.
   - All active missions are rendered with operational target markers (`🎯`).

2. **Visual Road Target Highlight Layer (`roads-mission-highlight`):**
   - Added a dedicated amber glowing casing (`#f59e0b`, width 10px, opacity 0.85, dashed `[2, 1]`) beneath the road status line.
   - Roads designated as active survey targets (e.g. `Road #2` "North Diagonal (Hub A→C4)") immediately illuminate on the map.

3. **Responsive Container & Tab Resilience (Phase 18):**
   - Attached a `ResizeObserver` to `containerRef.current` and a `window.resize` event listener calling `map.resize()`.
   - Switching between dashboard tabs, toggling sidebars, or resizing browser windows preserves full canvas dimensions without gray tiles or clipping.

4. **Responder Map Data Polling Loop (Phase 11 & 12):**
   - Added `loadMapData()` to the 8-second polling interval in `ResponderDashboard.tsx`.
   - Propagated road closures and hazard changes update the responder's tactical map automatically without requiring page reloads.

5. **Safe Evacuation Route Interactivity (Phase 7 & 10):**
   - Added interactive `click` and `mouseenter`/`mouseleave` pointer listeners on `route-line`.
   - Clicking the safe route opens a popup displaying target hub name, total distance in km, and routing safety criteria.

6. **State-Driven Legend & Empty States (Phases 13 & 14):**
   - Legend reflects **actual rendered objects** in the viewport.
   - If a layer has zero active items (e.g., no active hazards in sector), it displays a subtle informational empty state ("No active hazards") rather than misleading the operator.

7. **Citizen Geolocation Bounds Guard:**
   - In `CitizenDashboard.tsx`, if the browser's physical geolocation is outside the virtual city bounds, it defaults to the operational center `(20.552, 85.823)`, ensuring Dijkstra routing functions reliably.

## 5. Marker & Popup Behavior

### Safety Hubs
- **Visuals:** 34px circular marker with `🏥` glyph, thick white casing, drop shadow.
  - Green (`#10b981`): Open with ample capacity.
  - Amber (`#f59e0b`): Near capacity ($\ge 80\%$) or resource shortage.
  - Red (`#ef4444`): Full / Closed.
- **Popup Content:** Name, status badge, occupancy progress bar, available slots, resource shortfall warning badges (`Low Food`, `Low Water`, `Low Medical`), and an integrated `🧭 Calculate Safe Route Here` action button.

### Incident Clusters
- **Visuals:** 32px circular badge displaying report count (e.g. `2`, `9+`). Amber for unverified citizen reports; blue for mission assigned.
- **Popup Content:** Cluster ID, report count, dominant category, priority score, and quick dispatch button for coordinators.

### Mission Targets
- **Visuals:** 32px square badge with `🎯` glyph, color-coded by status (`in_progress`: blue, `accepted`: cyan, `assigned`: amber).
- **Popup Content:** Mission ID, title, mission type, assigned responder unit, target road/cluster description.

### Evacuation Route
- **Visuals:** Glowing dual-layer purple line (`#3b0764` casing + `#c084fc` core).
- **Popup Content:** Destination Safety Hub name, total road distance (km), and Dijkstra disaster-safety confirmation.
