## 3. Role-by-Role Implementation Details

### 3.1 Citizen UX (`/` / `/map`)
- **Map-First Priority**: Full viewport interactive MapLibre map centered on the operational area with real-time rendering of clear/hazardous/flooded/blocked roads, active hazard perimeters, and Safety Hubs.
- **Top Alert Banner**: Prominent banner displaying active official emergency alerts with direct navigation to Emergency Mode.
- **Bottom Action Bar**: Floating quick-action bar with:
  - **Safe Hubs**: Drawer showing real-time occupancy, capacity badges, and critical resource shortage warnings.
  - **Report Incident**: Simple crowdsourced incident reporting form (Category, Description, GPS picker) with offline buffering.
  - **Get Safe Route**: Dynamic evacuation route calculation to the nearest open, non-full Safety Hub avoiding blocked roads and critical hazard zones.
- **Truthful Offline Messaging**: Displays `"Offline — showing cached data. Reports will sync when connectivity returns."` and buffers citizen reports locally in IndexedDB as `pending`.

### 3.2 Responder UX (`/missions`)
- **Mission-First Split View**:
  - Left panel: Active assigned mission details, mission type badge, target coordinates, mission status transitions.
  - Right panel: Tactical map with responder current position marker and mission target crosshair marker.
- **Mission Lifecycle Machine**: Strictly enforces `ASSIGNED` $\rightarrow$ `ACCEPTED` $\rightarrow$ `IN_PROGRESS` $\rightarrow$ `COMPLETED` (or `REJECTED`).
- **2-Step Guided Field Survey**:
  - Step 1: Verification outcome (`confirmed_hazard`, `road_blocked`, `no_hazard_found`, `false_report`), hazard level slider (1–5), physical condition notes, media URL.
  - Step 2: Road operational assessment (road status, hazard/flood penalty, blockage toggle).
- **Explicit Ground Truth Propagation**: Submitting a survey does NOT automatically update operational ground truth. Responders/Coordinators use the explicit **Propagate Ground Truth** action calling `/api/v1/field-surveys/{id}/propagate` with server-side row-locking and route-cache invalidation.

### 3.3 Coordinator Control Room (`/coordinator`)
- **Operational Command Center**:
  - **Real-Time KPIs**: Blocked roads count, open incident clusters, critical hub shortages, active missions, available responders.
  - **5 Operational Tabs**:
    1. `Overview`: High-level operational posture, rapid responder directory.
    2. `Missions`: Direct mission dispatch form (Title, Type, Target Road/Cluster, Assignee) and live mission tracking.
    3. `Hubs`: Safety hub list with capacity bars, occupancy management, and resource threshold badges.
    4. `Incidents`: Aggregated incident clusters with report counts and one-click crew dispatch.
    5. `Alerts`: Official broadcast management (create EMERGENCY / WARNING / ADVISORY notices, deactivate active alerts).
- **Zero Simulation UI**: Removed all simulation controls, accordions, and simulation trigger buttons. The dashboard is 100% operational.

### 3.4 Dedicated Emergency Mode (`/emergency`)
- **High-Contrast Emergency Interface**: Full-screen layout prioritizing rapid action.
- **Critical Components**:
  - Active Emergency Alert notice with issued-by timestamp and instructions.
  - Nearest accessible Safety Hubs with occupancy metrics.
  - One-click Evacuation Route calculation.
  - SOS Emergency assistance trigger.
  - Truthful connectivity messaging (notifies citizen if dynamic recalculation requires internet access).

### 3.5 Disaster Relief & Campaigns (`/fundraising`)
- **Transparent Crowdfunding**: Public relief campaigns linked directly to verified `resource_requirements` from Safety Hubs.
- **Resource Categorization**: Badges and icons for `food`, `water`, `medical`, and `shelter_kit`.
- **Sandbox Donation Modal**: Real-time mock donations with custom donor name, preset amounts (₹500, ₹1000, ₹2500, ₹5000), personal message, and cryptographic transaction reference.

## 5. Offline-First & Sync Architecture Verification

- **IndexedDB Schema (`Dexie.js`)**:
  - `local_reports`: Stores citizen reports created offline with client timestamp and pending status.
  - `local_surveys`: Stores responder surveys created offline.
  - `cached_hubs`, `cached_roads`, `cached_alerts`: Read-through cached snapshots for offline viewing.
- **Sync Status Transparency**:
  - Citizen and Responder UIs clearly indicate when operating offline.
  - Offline submissions explicitly state `"Saved offline — will sync when connection is restored"`.
  - Server replay via `/api/v1/sync/replay` uses per-operation PostgreSQL savepoints and unique `operation_id` idempotency guards.
