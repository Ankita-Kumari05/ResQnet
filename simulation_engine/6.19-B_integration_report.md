## 1. Executive Summary

ResQnet 6.19-B completes and hardens the real end-to-end integration between the standalone **Simulation Engine** (running on port `9000`) and the **ResQnet Core Disaster Management Platform** (`FastAPI` on port `8000`, `PostgreSQL/PostGIS` on port `5432`, and `React/Vite` on port `5173`).

### Core Value Proposition & Architectural Proof
The Simulation Engine operates strictly as an **external side engine emulating external signals and observations**. It:
1. **Never directly accesses PostgreSQL/PostGIS** (zero SQL queries executed against ResQnet tables).
2. **Never manipulates React UI state directly**.
3. **Submits all events as standard HTTP requests** through ResQnet's authenticated REST APIs.
4. **Exercises real ResQnet business logic**: incident clustering (`cluster_incident_report`), role-based access control (RBAC), row-locked hub capacity transitions, mission lifecycle assignment, route cache invalidation, and Dijkstra graph weight recalculation.
5. **Visibly identifies all simulated signals** with explicit `[SIM]` tags and clear source attribution to ensure operational distinction between external observations and verified ground truth.

### Frozen Architecture Adherence
- **Zero Schema Changes:** DB schema is frozen at migration `71867cddef4b`. No tables or columns were added.
- **No Direct SQL Execution:** The Simulation Engine codebase contains zero imports of `psycopg2`, `asyncpg`, or `sqlalchemy` directed at ResQnet tables.
- **Strict Role Boundaries:**
  - `POST /api/v1/alerts` authenticated as `COORDINATOR`
  - Citizen reports authenticated as `CITIZEN`
  - Missions dispatched authenticated as `COORDINATOR`
  - Road block signal routed through designated simulation operational injection endpoint.
- **Truth Separation:** Citizen reports enter with `status = UNVERIFIED` (Tier-1 Signal). The road block event is labeled as an injected operational signal rather than a fabricated field survey verification.

## 15. Known Limitations

1. **Direct Operational Road Block Injection:**  
   The simulation event `ROAD_BLOCKED` injects a direct road blockage via `/api/simulation/events/road/block` to demonstrate routing detour in under 60 seconds. In the standard ResQnet field workflow, road blockages originate from a responder Field Survey and require Coordinator ground-truth propagation. During judge presentations, presenters should clarify that this event simulates an authoritative operational signal rather than a full responder field survey cycle.
2. **PostgreSQL WSL Idle Keepalive:**  
   When hosting PostgreSQL inside WSL2 on Windows, WSL may suspend background services if no active terminal remains open. The repository includes an automated keepalive daemon script (`wsl -d Ubuntu -e bash -c "sudo service postgresql start && sleep infinity"`).
